# Logers.Watch

### _What if streaming worked like a prepaid meter?_

We pay for Netflix every month. Last month, maybe 3 episodes. Still charged the full subscription — obviously. Streaming runs on the gym-membership model: the business wins every time you forget to cancel, and you're paying for content you never touched.

**Logers.Watch flips that.** You load tokens. You watch. You pay only for what you actually streamed — down to the segment. Stop watching, stop paying. Simple.

---

🔐 **Deposit** — Viewers deposit ERC-20 stablecoins (e.g. USDC) into a smart contract

▶️ **Stream** — Video is served in adaptive bitrate segments (DASH) — quality adjusts to your network, exactly like Netflix does it

💳 **Pay Per Segment** — Each segment request deducts from your balance in real time — you pay for what loads, nothing more

📡 **Live Balance** — Balance updates stream back to you live via WebSockets — watch your wallet tick

🌿 **Creator Payouts** — Creators claim accumulated earnings on-chain via Merkle proofs

💸 **No subscriptions. No thresholds. No gatekeeping.**

## How It Works

```text
  1. DEPOSIT         2. STREAM              3. BILL               4. CLAIM
  ─────────         ────────              ──────              ──────
  User deposits     Video segments are     Each segment         Creators claim
  ERC-20 tokens     delivered via DASH     deducts from the     cumulative earnings
  into the          adaptive bitrate       user's on-chain      on-chain using
  LogersWatch       streaming — same       balance in real      Merkle proofs
  contract          tech as Netflix        time via backend     generated by the
                                           billing engine       backend
```

- **Users** pre-fund viewing by depositing supported ERC-20 tokens on-chain.
- **Streaming** bills per-segment — only target video media segments are charged, not manifests or init segments.
- **Effective balance** = `onChainDeposit - totalConsumed - pendingDeduction` — always accurate, always real-time.
- **Creators** receive Merkle proofs and claim earnings directly from the contract. No intermediary holds their money.

Project maturity:

- Feature implementation is complete.
- Aggressive real-world testing and full production hardening were not completed.
- Treat this repository as a strong demo/prototype baseline.

## Features

### Core Functionality

- User and creator authentication with JWT and cookie support.
- Video upload and DASH processing pipeline (ffmpeg → adaptive bitrate segments).
- Segment-based watch billing with Redis-backed pending deductions.
- On-chain synced user balances (`balance`, `totalConsumed`, pending deductions).
- Creator Merkle proof generation and verification endpoints.

### Blockchain Capabilities

- On-chain user deposits via `deposit` (ERC-20 permit) and `depositWithoutPermit` (approve + transfer).
- Creator on-chain claim flow using Merkle proofs.
- Configurable platform fee in contract logic (default 10%).
- Supported token allowlist controlled by contract owner.
- Reentrancy-guarded claim function with role-based access control.

### Operational Features

- BullMQ-based background video processing worker.
- Scheduled Merkle root updates with idempotent root persistence.
- Admin routes for Merkle trigger/history/active root checks.
- WebSocket billing channel for real-time session and balance updates.

### Billing Model

| Concept | Value |
| --- | --- |
| Cost per segment request | `0.0002` tokens |
| Baseline segment duration | `4 seconds` |
| Cost per second | `0.00005` tokens |
| Platform fee | `10%` (configurable) |
| Earnings rate for creators | Configurable via `EARNINGS_RATE_PER_SECOND` |

**Effective balance at runtime:**

```
effectiveBalance = User.balance - User.totalConsumed - pendingDeduction(Redis)
```

Only when `effectiveBalance > segmentCost` is the segment delivered.

## Smart Contracts

### `LogersWatch.sol`

Main protocol contract in `contracts/src/LogersWatch.sol`.

**User functions:**

| Function | Description |
| --- | --- |
| `deposit(token, value, deadline, v, r, s)` | Deposit tokens using ERC-20 permit signature |
| `depositWithoutPermit(token, value)` | Deposit tokens using standard approve + transferFrom |

**Creator functions:**

| Function | Description |
| --- | --- |
| `claim(proof, totalEarnings, token)` | Claim earnings with Merkle proof verification (reentrancy-guarded) |

**Owner/Admin functions:**

| Function | Description |
| --- | --- |
| `setMerkleRoot(root)` | Update the Merkle root for creator earnings |
| `changePlatformFee(newFee)` | Update the platform fee rate |
| `addCreator(creator)` | Verify creator and grant claim role |
| `banCreator(creator)` | Revoke creator verification and claim role |
| `addNewTokenSupport(token)` | Add a supported ERC-20 token |
| `banTokenSupport(token)` | Remove token support |

**Getters:**

| Function | Returns |
| --- | --- |
| `getTotaldepositedByUser(user)` | Total deposited by a user |
| `getTotalWithdrawnByCreator(creator)` | Total claimed by a creator |
| `getPlatformFee()` | Current platform fee rate |
| `getCreators()` | Array of all added creators |
| `getSupportedTokens()` | Array of supported token addresses |
| `getTokenStatus(token)` | Whether a token is supported |
| `getCreatorStstus()` | Whether caller is a verified creator |

### Merkle Claim Pipeline

1. Collect creators with linked wallet addresses.
2. Convert watch time to whole-second deterministic values.
3. Compute token-unit earnings (`EARNINGS_RATE_PER_SECOND`, token decimals aware).
4. Build Merkle tree and generate proof rows.
5. If root changed, call on-chain `setMerkleRoot`; if unchanged, keep idempotent.
6. Store active root + proofs in database.
7. Creator fetches proof from `/creators/me/claim-proof`.
8. Creator calls `claim(proof, totalEarnings, token)` on-chain.

## Installation

### Prerequisites

- Node.js `>=20`
- Bun `>=1.1`
- Docker + Docker Compose
- Foundry (`forge`, `cast`, `anvil`)
- `ffmpeg` (required for video processing pipeline)

### Setup

```bash
# Clone the repository
git clone https://github.com/Atul-ThakreLO/Logers.Watch.git
cd Logers.Watch

# Start infrastructure (Postgres + Redis)
cd backend
docker compose up -d

# Backend dependencies and Prisma
bun install
bun run db:generate
bun run db:migrate

# Frontend
cd ../frontend
npm install

# Contracts (optional for local app run, required for contract work)
cd ../contracts
forge build
```

### Environment Variables

Create:

- `backend/.env`
- `frontend/.env.local`

Backend example:

```env

JWT_SECRET="change-this"
ADMIN_API_KEY="change-this"

REDIS_HOST="localhost"
REDIS_PORT="6379"
RPC_URL="https://..."
RPC_FALLBACK_URL="https://..."
CHAIN_NAME="sepolia"
LOGERS_WATCH_CONTRACT_ADDRESS="0x..."
SUPPORTED_TOKEN_ADDRESS="0x..."
ADMIN_KEYSTORE_NAME="..."
ADMIN_KEYSTORE_PASSWORD="..."
ENABLE_MERKLE_CRON="true"
```

## Security Considerations

- Admin endpoints require admin API key or admin JWT.
- Creator claim depends on valid active Merkle root and proof.
- Claim function is protected by `ReentrancyGuard` and role-based `AccessControl`.
- Streaming endpoint validates segment names to reduce path traversal risk.
- Merkle updater has in-flight lock to avoid overlapping runs.
- RPC fallback support exists (`RPC_FALLBACK_URL`) for resilience.

**Important:** This codebase has not undergone a full external security audit.
